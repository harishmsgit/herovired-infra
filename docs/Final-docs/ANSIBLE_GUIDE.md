# Ansible Configuration & Management Guide

## Overview

Ansible is the **Configuration Management** tool that automates post-infrastructure setup. After Terraform creates the AWS infrastructure, Ansible configures the management host and prepares the EKS cluster for application deployment.

---

## What Ansible Does

### 1. **Management Host Configuration** (configure-management.yml)
```
Management EC2 Instance (Ubuntu 22.04)
├── Install Docker Engine
├── Install kubectl (EKS CLI)
├── Install Helm 3 (Kubernetes package manager)
├── Configure kubeconfig (EKS authentication)
├── Setup Kubernetes namespaces
├── Install ExternalSecrets operator
├── Configure AWS IAM authentication
└── Validate all components
```
**Purpose**: Turns raw EC2 instance into Ansible control node + Kubernetes administrator

---

### 2. **EKS Cluster Setup** (configure-management.yml)
```
Post-Cluster Provisioning:
├── Apply namespace YAML (shopnow-ns)
├── Create ServiceAccounts with IAM roles (IRSA)
├── Install ExternalSecrets operator
├── Configure AWS Secrets Manager integration
├── Apply RBAC policies
├── Deploy persistent storage (MongoDB StatefulSet)
└── Configure monitoring (Prometheus, Grafana)
```
**Purpose**: Configures Kubernetes cluster for application workloads

---

### 3. **Network & Security Configuration**
```
Security Groups:
├── Management → EKS (kubectl communication)
├── Management → MongoDB (port 27017)
├── EKS Nodes → ECR (image pull)
└── Application → MongoDB (via Kubernetes DNS)

Firewall Rules:
├── Ingress: Allow GitHub runners → Management SSH
├── Ingress: Allow Management → EKS API
└── Egress: All outbound traffic allowed
```
**Purpose**: Secure communication paths between components

---

### 4. **Authentication & Authorization**
```
IAM Authentication Flow:
1. Ansible runs on Management EC2
2. EC2 has IAM role with permissions
3. Credentials available in EC2 metadata service
4. kubectl uses AWS IAM credentials (no kubeconfig password)
5. Kubernetes IRSA: Pods get temporary AWS credentials

Benefit: Zero credential storage needed
```
**Purpose**: Secure, keyless authentication

## Most Frequent Changes in Production

### 1. **Adding Kubernetes Namespaces** ⭐⭐⭐
**When**: New team/project joins infrastructure
```yaml
# In roles/eks_setup/tasks/main.yml
- name: Create application namespace
  kubernetes.core.k8s:
    name: shopnow-ns
    api_version: v1
    kind: Namespace
    state: present

# Then update Kustomize overlays for namespace-specific configs
```

---

### 2. **Updating Docker/Kubernetes Versions** ⭐⭐⭐
**When**: Security patches or feature updates required
```yaml
# In roles/prerequisites/tasks/main.yml
- name: Install Docker
  shell: |
    curl -fsSL https://get.docker.com | bash
    # Updates to latest Docker version

- name: Install kubectl (latest stable)
  shell: |
    curl -L https://dl.k8s.io/release/stable.txt | xargs -I {} \
    curl -LO "https://dl.k8s.io/release/{}/bin/linux/amd64/kubectl"
```
**Impact**: Rolling restart of management host (brief downtime)

---

### 3. **Configuring New IAM Roles for Pods** ⭐⭐
**When**: Application needs AWS API access (S3, SQS, SNS)
```yaml
# In roles/security/tasks/main.yml
- name: Create IAM role for backend service
  community.aws.iam_role:
    name: shopnow-backend-pod-role
    assume_role_policy_document: "{{ lookup('template', 'pod-trust-policy.json') }}"
    managed_policies:
      - arn:aws:iam::aws:policy/AmazonS3ReadOnlyAccess
      - arn:aws:iam::aws:policy/AWSXRayDaemonAccess

# Bind to Kubernetes ServiceAccount (IRSA)
```

---

### 4. **Scaling Replica Counts** ⭐⭐
**When**: Application needs more capacity
```yaml
# In kubernetes manifests (managed by Ansible via kubectl)
apiVersion: apps/v1
kind: Deployment
metadata:
  name: backend
spec:
  replicas: 3  # was 2, now 3
  # ...
```
**Ansible apply**:
```bash
ansible-playbook playbooks/configure-management.yml \
  -e "replicas=3"
```

---

### 5. **Adding Monitoring & Alerts** ⭐⭐
**When**: Need visibility into application metrics
```yaml
# In roles/monitoring/tasks/main.yml
- name: Deploy Prometheus
  kubernetes.core.helm:
    name: prometheus
    chart_ref: prometheus-community/kube-prometheus-stack
    namespace: monitor-ns
    values:
      prometheus:
        scrapeInterval: 30s
```

## Ansible Management Tasks

### **Running Playbooks**

#### **Initial Setup (from Jenkins pipeline)**
```bash
cd herovired-infra/ansible

# Run configure playbook (provision everything)
ansible-playbook playbooks/configure-management.yml \
  -i inventories/generated/hosts.ini \
  -e "aws_region=ap-south-1" \
  -e "eks_cluster_name=shopnow-app-eks"

# Expected output: Shows each task and OK/CHANGED status
```

#### **Idempotent Verification**
```bash
# Run again - should show all "ok" (no changes)
ansible-playbook playbooks/configure-management.yml \
  -i inventories/generated/hosts.ini

# If anything shows "CHANGED", configuration was missing
```

#### **Validate Setup**
```bash
ansible-playbook playbooks/validate-management.yml \
  -i inventories/generated/hosts.ini

# Checks:
# ✓ Docker running
# ✓ kubectl can connect to EKS
# ✓ All namespaces exist
# ✓ All pods are running
# ✓ Ingress is accessible
```

---

### **Manual Task Execution**

#### **Install/Update Single Component**
```bash
# Only run Docker installation role
ansible-playbook playbooks/configure-management.yml \
  --tags "docker"

# Available tags: docker, kubectl, helm, eks_setup, monitoring, security
```

#### **Run on Specific Hosts**
```bash
# Only run on management host (not EKS nodes)
ansible-playbook playbooks/configure-management.yml \
  -i inventories/generated/hosts.ini \
  -l management

# Other hosts/groups: eks_masters, eks_workers, all
```

#### **Dry-run (Check Mode)**
```bash
# Show what would change without making changes
ansible-playbook playbooks/configure-management.yml \
  -i inventories/generated/hosts.ini \
  --check

# Use this before production runs
```

#### **Verbose Debugging**
```bash
# Show all tasks and their output
ansible-playbook playbooks/configure-management.yml \
  -i inventories/generated/hosts.ini \
  -v

# Even more verbose:
ansible-playbook ... -vvv  # debug all variables and tasks
```

---

### **Inventory Management**

#### **View Current Inventory**
```bash
# List all hosts
ansible-inventory -i inventories/generated/hosts.ini --list

# List specific group
ansible-inventory -i inventories/generated/hosts.ini --host management

# Example output:
# management:
#   ansible_host: 10.20.1.50  (private IP)
#   ansible_user: ubuntu
#   ansible_ssh_private_key: ~/.ssh/shopnow-key-pair.pem
```

#### **Generate Inventory from Terraform**
```bash
# Automatically run by Jenkins (scripts/generate_ansible_inventory.py)
python3 scripts/generate_ansible_inventory.py \
  --terraform-output terraform-outputs.json \
  --inventory inventories/generated/hosts.ini \
  --remote-user ubuntu

# Creates hosts.ini with Terraform outputs:
# - Management EC2 IP
# - EKS cluster endpoint
# - VPC CIDR blocks
```

## Common Patterns & Examples

### **Pattern 1: Install Software on Management Host**
```yaml
# In roles/prerequisites/tasks/main.yml
- name: Install Helm
  get_url:
    url: "https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3"
    dest: /tmp/get_helm.sh
    mode: '0755'
  register: helm_script

- name: Run Helm installer
  shell: /tmp/get_helm.sh
  when: helm_script is changed
```

---

### **Pattern 2: Deploy Kubernetes Resources**
```yaml
# In roles/eks_setup/tasks/main.yml
- name: Apply Kubernetes manifests
  kubernetes.core.k8s:
    state: present
    definition: "{{ lookup('template', 'namespace.yaml.j2') }}"
    kubeconfig: /home/ubuntu/.kube/config

# Supported resources: Deployment, Service, ConfigMap, Secret, StatefulSet, etc.
```

---

### **Pattern 3: Templating Configuration Files**
```yaml
# roles/monitoring/templates/prometheus-config.yaml.j2
global:
  scrape_interval: {{ scrape_interval | default('30s') }}
  external_labels:
    cluster: {{ eks_cluster_name }}
    environment: {{ environment }}

# In tasks:
- name: Deploy Prometheus config
  kubernetes.core.k8s:
    definition: "{{ lookup('template', 'prometheus-config.yaml.j2') }}"
```

---

### **Pattern 4: Conditional Execution**
```yaml
# Execute based on environment
- name: Configure production monitoring
  block:
    - name: Deploy production-grade Prometheus
      # ...
  when: environment == "prod"

# Execute based on variable
- name: Create backup resources
  # ...
  when: enable_backups | default(false)
```

## Troubleshooting

### **Connection Issues**
```bash
# Test SSH connectivity
ansible-inventory -i inventories/generated/hosts.ini --host management

# Manually SSH to verify
ssh -i ~/.ssh/shopnow-key-pair.pem ubuntu@<management-ip>

# Fix SSH key permissions
chmod 600 ~/.ssh/shopnow-key-pair.pem
```

### **Kubernetes Connection Issues**
```bash
# Run on management host:
kubectl cluster-info
kubectl get nodes
kubectl get pods -A

# Check kubeconfig
cat ~/.kube/config | grep cluster-name

# Verify AWS credentials
aws sts get-caller-identity
```

### **Playbook Failures**
```bash
# Re-run with verbose debugging
ansible-playbook ... -vvv 2>&1 | tee playbook-debug.log

# Check Ansible logs
less /var/log/ansible.log  # if configured

# Validate playbook syntax
ansible-playbook playbooks/configure-management.yml --syntax-check
```

## Security Considerations

### **SSH Key Management**
```bash
# Keys stored in Jenkins credentials (secret)
# Never commit to Git

# Generate new key pair:
ssh-keygen -t rsa -b 4096 -f shopnow-key-pair

# Store in AWS Secrets Manager:
aws secretsmanager create-secret \
  --name shopnow/ec2-ssh-key \
  --secret-string file://shopnow-key-pair
```

### **Sensitive Data**
```yaml
# Never log passwords/tokens
- name: Create secret
  kubernetes.core.k8s:
    definition: "{{ lookup('template', 'secret.yaml.j2') }}"
  no_log: true  # Prevents logging

# Use Kubernetes Secrets (not Ansible vars)
- name: Reference secret in pod
  kubernetes.core.k8s:
    definition:
      containers:
        - env:
          - name: DB_PASSWORD
            valueFrom:
              secretKeyRef:
                name: mongodb-secret
                key: password
```

### **RBAC Configuration**
```yaml
# Least privilege for service accounts
- name: Create restricted service account
  kubernetes.core.k8s:
    definition:
      apiVersion: v1
      kind: ServiceAccount
      metadata:
        name: backend-service-account
        namespace: shopnow-ns

# Bind to role with limited permissions (not cluster-admin)
```

## Integration with Application Deployment

### **Application → Infrastructure Sync**

1. **Application team defines deployment requirements**
   ```yaml
   # In shopNow/deployment.yaml
   spec:
     replicas: 3
     resources:
       requests:
         memory: "256Mi"
         cpu: "100m"
       limits:
         memory: "512Mi"
         cpu: "500m"
   ```

2. **Ansible applies to EKS cluster**
   ```bash
   ansible-playbook deploy.yml \
     -e "replicas=3" \
     -e "image_tag=v1.2.3"
   ```

3. **Kubernetes validates and schedules pods**
   - Checks available resources on nodes
   - Pulls images from ECR
   - Mounts volumes
   - Applies network policies

4. **Application runs with infrastructure backing**
   - Can reach MongoDB via Kubernetes DNS
   - Has AWS credentials via IRSA
   - Logs sent to CloudWatch

## Maintenance Checklist

| Task | Frequency | Impact |
|------|-----------|--------|
| Run configure playbook | Monthly | Medium (rolling restart) |
| Validate configuration | Weekly | None (check mode) |
| Update Kubernetes version | Quarterly | High (plan accordingly) |
| Review RBAC policies | Quarterly | None (audit only) |
| Rotate SSH keys | Annually | Medium (one-time update) |
| Backup kubeconfig | Weekly | None (local backup) |

## Summary

| Aspect | Details |
|--------|---------|
| **Purpose** | Configure EC2 management host and EKS cluster for applications |
| **Update Frequency** | Monthly (config changes) to Quarterly (version upgrades) |
| **Common Changes** | Scaling replicas, adding namespaces, updating versions |
| **Risk Level** | Medium (can interrupt services if misconfigured) |
| **Rollback** | Manual (revert playbook and reapply) |
| **Learning Curve** | 1-2 weeks to master |
